# Lessons learned

- Spoken-source edits must bind both original freshness and the corrected owned proof. Match canonical records against the old source, then map approved audit decisions against the verified new source. Reuse the same eligible corpus snapshot as the audit; an unfiltered reload changes overlap/target context and invalidates otherwise matching proof.

- Preserve a source-grounded subject rather than an erroneous heading. A correcting citation is not misplaced evidence, and legacy words inside stable IDs/slugs are not claims. Test both false quarantine and genuine topic mismatch; version changed policies before reusing pending approvals.

- Local HTTP verification can inherit an environment proxy even for localhost. Use a proxy-free opener for the temporary preview; a successful HTTP status alone does not prove the full page body was received.

- A missing topic row may be real but too far away for a valid citation. Check actual elapsed time before expanding:the backhand-push topic-to-pinch span is60.267seconds. Preserve separate bounded records and per-clause ownership instead of exceeding30seconds,guessing a trim or silently treating nearby context as support.

- A prohibition is not always its strict positive inverse: “not below” does not mean “strictly above.” Preserve spoken boundary wording when the physical reference is ambiguous. Write compound negatives explicitly so “not left leg or behind” cannot become an instruction to place weight behind the player; retain the source's stroke/phase condition.

- Preserve phase and role, not only vocabulary: meeting/brushing during a stroke must not become a separate later phase, and an observed reliance on borrowed power must not become advice to use it. Keep contact-only finger-force wording separate from independently described speed generation. Direct public prose can preserve uncertainty without publishing model-review commentary.

- Do not borrow an object from one citation to complete a different source's personal spacing example. Preserve the speaker's experience scope and leave an unspecified measured object unspecified. When a verifier rejects an alias, inspect all owned rows: an explicit complete “looping cross-court” sentence outweighs a mistaken absence claim. Changed advisory overlaps need their own current review, even after valid applications.

- When a parent runner already owns the KB lock, remove a redundant child write stage where publication already performs that work. Do not fix direct-command contention with a lock-bypass flag. Test the direct write's pause/lock boundary and retain the parent's lock through publication.

- Verify the last semantic value that is saved, not only its earlier candidate. Grammar cleanup can invent causality, and a formatting/overlap check cannot preserve source support after a rewrite. Exercise every direct canonical-writing command against pause and lock controls; guarding the main runner alone is insufficient.

## 2026-10-12

- Fairness must reach the actual candidate calls; source-balanced video pools do not guarantee fair ten-proposal queue slices.
- A retry needs a changed input, due retry policy, or useful failure feedback. Repeating the same semantic decision cannot reliably fix a deterministic boundary failure the model cannot see.
- Measure redundant serialization separately from model latency; preserve checkpoint recovery while removing duplicate successful-exit writes.
- A fixed ten-item checkpoint already identifies whether a final flush is needed: use the partial-batch remainder and existing dirty set instead of adding another persistence state machine. Test unchanged file bytes/mtimes alongside saved decisions.
- Confirm monitor state through its local status API. A process command-line search can miss a running service; a stopped loop is distinct from an absent monitor.
- Browser polling is not durable run telemetry. Persist history with the processing artifact, keep the viewer read-only, and retain unchanged observations and a time-window boundary anchor. Use elapsed time on chart axes and label missing history rather than synthesizing old counts.

## 2026-09-19

- Apply the citation contract to relation claims as well as evidence; keeping a review-status field does not enforce it during publishing.
- When review adds adjudicated segment IDs, update every completion consumer, not only validation. Share that small accounting function.
- Gitignore changes prevent new additions but do not remove tracked private state or history. Report the distinction explicitly.

## 2026-09-15

- A streamed child process can still leave the operator view blank when a stage itself emits no output. Keep the machine-readable stage markers, add privacy-safe elapsed heartbeats at the orchestrator boundary, and copy only recognized summaries into the human-facing monitor log.
- Counts in an operator dashboard need their unit beside the number. A data field named `pending` is still ambiguous unless the UI says whether it counts videos, candidate proposals, concepts, or evidence moments.
- Automatic editorial placement must use evidence already present on a newly accepted concept; a summary generated in a later stage cannot be the only signal or publication can fail on an otherwise valid acceptance.

## 2026-09-08

- Long Codex batches must persist queue and canonical-document progress before the stage timeout; an atomic write only at batch end can make a timed-out run repeat the same work forever.
- A checkpoint interval is not a batch-size limit. Report and enforce both separately when a long retry workset must become resumable ten-item cycles.

## 2026-08-05

- Do not assume `sources.yaml` video membership is the live workset. In this project it accumulated configured batch history, while `run-cp.py` continued through discovery entries without appending them.
- Show the discovered partition and the public-corpus equation separately, with their overlap stated numerically.
- Lead a mixed public/operator dashboard with the user-facing content state, then preserve configuration and pipeline mechanics in a visibly subordinate operator section with an explicit definition.
- Configuration-only exclusion counts can materially understate full-catalog eligibility: derive members-only, subtitle, retry, and completion states from the complete inventory plus durable retry evidence before explaining the not-on-site group.
- A limited automatic review pass needs both a check limit and an explicit selected-video filter; a candidate-count limit alone does not make the run manifest an exact description of the work performed.
- A convenience launcher must start every service named by its operator-facing purpose and verify readiness; starting only the site made the separate processor monitor easy to assume was active.
- A launcher that starts a hidden service must own its lifecycle explicitly: Ctrl+C only reaches foreground children, and a later launch must stop the verified old service before checking readiness or it can silently reuse stale in-memory UI code.
- Operational resource panels should default to the process tree the operator can act on. Whole-machine load and unrelated language-runtime processes make project diagnosis noisier, not clearer.
- Dynamic status cards should reserve space for their longest normal states; otherwise changing countdown, active-run, and outcome strings cause nearby controls to jump even when their font sizes are technically consistent.
- A human-review UI must make the exact cited captions visually distinct from nearby context, require an explanatory audit note and explicit claim/concept confirmations, and block canonical writes while automation can mutate the same queue.
- A wide operational monitor benefits from a true 50/50 primary split: keep the active log readable without letting it crowd status, resource, and event panels into a fixed narrow rail.
- A small batch is not fair merely because it is finite. If the underlying ledger is source-sorted, slicing the first 50 can indefinitely hide progress elsewhere; rotate through sources before applying the limit and report human assignment separately from completion.

## 2026-08-12

- Real transcript segment IDs and valid YouTube timestamps prove provenance, not semantic support. Validation must also establish that the retained caption text entails the published claim and maps to the stated concept.
- Never keep a rationale synthesized from multiple distant transcript clusters after selecting only one cluster. Split the propositions, retain all necessary contiguous support, or defer the candidate for review.
- A model-supplied `matched_concept_id` must not override a contradictory `resolution: new`, and high confidence must not substitute for concept-identity review.
- Automatic triage is not editorial completion. Completion metrics must separately report machine decisions, human decisions, canonical approval, and publication.
- A playback source window must enclose the complete duration of every cited segment. Any extra listening context belongs in a separate reviewed field.
- Summary presence is not summary quality: deterministic concatenation can satisfy the schema while producing fragmentary or misleading wiki prose.
- Human review is not the only valid semantic gate. A separate schema-constrained Codex adjudication call can be the default when it sees exact transcript context, is forced to select supplied IDs, records model provenance, and is followed by deterministic fail-closed validators; human input can remain optional advice or an explicit override.
- Quarantine is safer than trying to rewrite thousands of suspect records in place. Preserve legacy provenance, mark unsafe concepts/evidence unreviewed, publish only the trusted subset, and restore each topic only after fresh adjudication.
- Structured-output schemas must make nullable fields required when the CLI schema validator expects every property in `required`; an optional default can fail before model execution even though Pydantic accepts it locally.

## 2026-08-30

- When a public corpus contracts after a safety migration, reconcile canonical files, approved records, published records, and inventory separately before calling it data loss.
- A failed recovery cycle can leave the last safe publish unchanged while private queue work continues to accumulate; always report the last successful publish timestamp alongside the current processor failure.
- Model-output invariants need an operational failure policy as well as a schema: a single malformed adjudication response should identify the item and remain retryable without silently publishing partial work.
- Generated ledgers need the same Windows replace retry policy as generated YAML. A transient antivirus or indexer handle on an atomic destination can otherwise abort a long batch at budget reconciliation; keep the last readable target intact and retry only briefly.

## 2026-08-04

- A successful base language such as `en` should remain the first choice; caption adapters need a source-track fallback for regional variants such as `en-US` without treating YouTube translation-language listings as original captions.
- When the processor monitor is active, source-only processor changes can be prepared and tested without starting another run, but validation/publish must wait for the active generated-data cycle to become idle.
- Cumulative per-process CPU seconds are useful for the detail list but not for current load; the monitor should expose a separate system CPU/memory snapshot and short history for operational decisions.
- When a progress table mixes videos, candidate proposals, evidence moments, concepts, and visual intervals, percentages alone are not enough; a relationship graph must explicitly mark unit changes and show exclusions or parallel review states as branches rather than sequential steps.
- Feature parity reviews should separate content coverage, shared UI behavior, and first-class domain modeling; a generic concept arrow is not evidence of a directional opponent tactic.
- Updating a scheduler's cooldown value is incomplete if an already-armed timer keeps its old deadline; an idle loop must clear and rebuild the timer, while an active run should defer rescheduling until completion.

## 2026-07-20

- A subprocess exit code without captured stdout/stderr is not an operational diagnosis. Unattended stages should preserve bounded output and a machine-readable outcome/reason.
- Retry reporting should distinguish a failed cycle from a scheduled retry and reset its consecutive-failure counter only after a successful complete cycle.

## 2026-07-21

- On Windows, terminating the monitor's parent cp process does not reliably terminate nested Python discovery workers. Stop handling must terminate the verified process tree and discovery stages need bounded timeouts after sleep/network resumes.
- Atlas placement needs to be checked against the full editorial context: label, definition, facets, evidence summary, and evidence reasons. A concept can pass label-based checks while its summary clearly belongs to a receive, push, fundamentals, or practice branch.
- Deterministic evidence-summary cleanup must cover reporting constructions embedded mid-sentence, not only prefixes; run the repository-wide generated-summary assertion after changing sanitizer rules.
- Alternate transcript routes must use a separate normalized-data namespace; overwriting a caption cache can invalidate reviewed segment references even when video IDs match.
- Published-only queue validation must compare accepted queue citations with reviewed canonical concepts, not sanitized published concepts that intentionally remove demo/private evidence.

## 2026-10-13

- Separate applying a setting from starting work before disabling Start during an active loop. Restore saved input once so status polling does not erase an operator’s draft.

- A monitor serves HTML/CSS loaded at startup. Complete UI work by reloading the idle service and checking the actual route; a separate preview alone does not make changes visible to the operator. Preserve loop intent and cooldown during the reload.

- Extracted candidate IDs can collide within a video. Preserve editorial state by content fingerprint as well as ID, and test rebuilds with two distinct proposals sharing an ID. Losing retry counts can conceal starvation as apparently new work.

- A valid citation envelope can still omit the line supporting one clause of an excerpt. Preserve required qualifiers (such as grip and near-end-line depth) in definitions, and compare the whole claim with selected rows rather than nearby context.

- Identical citation IDs can conceal distinct or unsupported excerpt claims. Read the full cited rows before consolidating; preserve distinct supported details in complete windows and quarantine wrong topic roles rather than rewriting them into another concept without review.
- A deterministic summary that falls back to a reviewed definition must include that definition in its invalidation fingerprint.

- A multi-part citation may repeat a full proposal description against each tiny split fragment. Review each part independently; consolidate equivalent fragments into complete supported windows and keep genuinely distinct instructions separate. A spoken technique label alone cannot certify a visual mechanics comparison.

- Shared words such as contact, upper half, and spin do not establish topic identity. Preserve which object is described: ball surface, racket surface, spatial position, hand mechanics, and force generation require separate support/mapping. A topic summary can conceal this distinction even when each citation text is plausible.
- At a video end, normalized caption duration may exceed cached metadata duration. Quarantine the incomplete citation until timing is reconciled; do not invent a clipped source envelope.

- Risk-selected spot checks cannot establish completeness. Persist an exhaustive article/citation/relationship/visual inventory and source fingerprints; mark the whole current article only after every unit is reviewed. Validation and old samples must not be credited as semantic completion.
- Freeze both the monitor loop and the scheduled processing task when the operator requests a stable full audit; keep the previous state for deliberate resumption. A repair invalidates its prior review, which must be rechecked against fresh source/content inputs.

- A full coverage ledger is not an execution process. Keep whole-corpus mechanical checks, bounded semantic proposals, independent repair/recheck, and strict completion gating distinct; persist failures and ambiguity rather than silently skipping them.
- Scope a semantic check to its unit: article summaries may synthesize several sources, while an individual citation must support its own prose. Do not let a model flag a label because another citation has a boundary issue, or treat spoken introductions as editorial scaffolding. Pilot/version the prompt before running the whole corpus.
- Missing transcript origin must not default a known generated provider track to manual. Derive only from the captured provider Boolean, preserve explicit origin/other-provider data, and keep raw captions/timestamps untouched.

- YAML fields span logical values, not single physical lines. Summary insertion must follow the entire definition, and replacement must cover folded/literal/quoted/plain summaries plus wrapped metadata. Test parseability and unchanged adjacent values across formats; don't tie writer fixtures to a live article's old wording.

- Before manually repairing the same defect across a corpus, inspect its producer and publication boundary. A boilerplate-generating fallback and clamped timing validator can recreate or conceal the issue even when individual repairs pass structural tests. Batch drafting must preserve complete source/unit coverage and receive a separate support review; model confidence, repeated text and tiny duration overshoots do not prove correctness or error.

- Round-trip YAML emission can drop quotes in existing flow lists even though the round-trip reader accepts the result. Preserve quoted scalars and validate emitted canonical/archive text through the production safe reader before replacement. Recovery must retain exact original bytes and reject unrelated edits.
- Live constrained-output schemas need required properties on inline variants, and typed facet lists avoid unsupported dynamic inline object maps. Reuse source-ID enum pools, restrict edits per unit, and retain runtime checks. Mocked transport tests do not establish backend schema acceptance.
- A previously repaired article is not a perfect calibration control: a second source review found that a foot-placement reason still inferred a causal link to backhand space. Reopen confirmed findings and keep the all-corpus gate closed. Separate source checks and deterministic public-scaffolding guards are both needed; two model passes can still share mistakes.

- A large-article reducer assembles untrusted proposals; it cannot adjudicate empty transcript input. Give it an assembly-specific contract, then independently verify the resulting values against exact selected rows. A draft's uncertainty must not skip that bounded source check; only oversized proof or footage requirements justify a deterministic deferral.
- Runtime rejection of contradictory edits is essential, but enforce representable rules in the response schema too. A unit cannot both quarantine and rewrite a record, and an article field has one replacement value.
- Content/source fingerprints do not capture new editorial findings. Include confirmed primary needs-fix notes in repair identity and application freshness; never let a model-supported plan bypass a later source-grounded primary finding.
- Verification must receive one consistent proposed article. Repeating the old heading/definition beside edited field values made the model flag removed clauses; mirror proposed topic fields and label old editorial context separately from claims and proof.
- Array length does not guarantee complete unit coverage in constrained model output. Require every requested unit key in the wire schema, check nested key agreement, and normalize through the existing typed boundary. A quarantined record's verification payload must also carry its proposed unreviewed status so verification and application assess the same result.
- Keep ordinary release verification separate from full semantic audit completion in every current planning surface. Preserve dated measurements as history, and refresh the rendered backlog from its Markdown source after updating coverage; a green build does not clear unchecked claims or unseen footage.
- An independent source verifier must not receive prior confidence or approval as part of the claim. Omit those processing fields at the shared model-input boundary, while retaining actual text, source/visual metadata, owned IDs and explicit quarantine disposition; preserve full proposed objects for deterministic application checks. Test both retained and excluded records and replay a real blocked case.
- Two model passes accepted a hand-position inference from an unfinished caption clause even after the primary finding warned against it. Keep only the complete supported instruction, preserve the rejected proposal for frozen accuracy evaluation, and never treat a second same-model verdict as a substitute for complete primary source review.
- Do not invalidate an entire audit campaign for a verifier-only change. Cache each stage against its actual inputs/policy, retain valid dependencies and park unchanged exceptions. Measure calls/tokens per resolved unit; repeated full drafts, rechecks and chat inspection can consume more than the useful repairs.

- Scope cache reuse to proposed claim, source ownership/text, full article fields, topic/targets/overlaps/context/metadata, model/policy and primary findings. Cache rejected verdicts too: unchanged output must not obtain approval through repeated stochastic retries. Keep stage policy versions separate from application versions and retain original call provenance.
- Compaction assertions can establish source preservation and smaller requests, not accuracy or billed-token savings. The two real GPT-6 Luna controls still accepted a known unsupported referent; preserve primary source review and treat the frozen defect as unresolved.

- Do not equate a supported effort setting with an evaluated effort choice. Luna reviewer guidance starts at high, while low is suited to routine tasks. Isolate effort from prompt changes: here high alone still falsely accepted the same referent, while explicit incomplete-clause actor/object grounding corrected the frozen pair. Two controls do not establish corpus-wide accuracy. Record actual effort/provenance and invalidate stale caches.

- Separate general applicability from a specific mechanism: a source saying a fundamental push works short/long does not extend a wrist-flick spin claim stated for a long push to short pushes. Luna/high verifier 1.1.1 still accepted this merge; primary review must inspect each condition, and frozen controls should retain the actual false acceptance.

- A schema allowing all nullable edit channels can represent an invalid clear as text null plus strings [] or facets []. Force unused channels to null per editable field while preserving runtime checks and valid null clears. Stricter representation of the same accepted outputs does not require replaying valid source judgments.
- Continuing after every transport failure can churn through dozens of unchecked articles during one outage. Stop after three consecutive fresh transport errors; cached stages must not reset the counter. Keep failed checkpoints and distinguish attempted jobs from reviewed coverage; resume only after inspecting recovery.

- Source-only Codex jobs should not depend on Apps connector startup. Per-run features.apps=false removes that unnecessary component without changing global app settings; test every command path and record effective capability in provenance. A supported CLI flag and mocked command tests do not establish live startup recovery or billed-token savings; measure those on actual work after the current lock owner finishes.

- Audit freshness checks must reuse the published input filter (approved, non-demo evidence and approved relations). Comparing unfiltered canonical YAML with a published-plan fingerprint can produce false mismatches; reuse _published_audit_inputs before assuming concurrent edits.
- Distinguish original owned source rows from the draft's chosen supporting IDs. A verifier can correctly reject a claim under an unnecessarily reduced support list while the original citation already contains its exact qualifying continuation. Review and restore real support rather than deleting true distinctions; ordinary contiguous anaphora is different from an unfinished unknown-object clause.
- A bat-face name is not a stroke-side classification: hook-serve backhand surface does not automatically establish a backhand stroke. Preserve the actual face/grip instruction and review the topic/side mapping separately.

- Measure accepted/corrected units and input/revision token shares before enlarging an audit budget. Repair-first drafting plus revision plus primary rereview can spend heavily without advancing published clearance. Reuse exact reviewed plans, audit original content before rewriting, and release planning locks for small reviewed application batches. Machine agreement is not a substitute for source review.

- Independent primary review applies to a particular proposed plan, not automatically its original YAML. Import against exact plan/source fingerprints; an imported rejection must block application, and a changed final plan needs fresh review. Preserve complete source verdicts and use actual dependencies when reusing unchanged work.

- A cheaper audit can expose more model false passes even with the same Luna/high policy; the source-based pilot must report that failure honestly. Preserve primary-known corrections as vetoes, require an exact final primary-review artifact before applying new plans, and keep raw model agreement separate from publication eligibility. Never report fewer calls as verified tokens-per-resolved-unit savings.

- Applying one reviewed article can stale a neighboring ready plan through overlap definitions. Stop at the guard, reselect truly fresh plans and park changed dependencies for targeted recheck. Do not let one stale item block unrelated fresh applications or silently replace its old approval. Nullable-field removals and reversible citation quarantines must reconcile original versus current audit-unit counts explicitly.

- A targeted prose repair can introduce a stronger technical action: key point at a location does not establish aim the serve toward it. Recheck final wording against every owned clause, and keep no-op unsupported ratings unresolved. Reusing correct surrounding units does not remove final primary review.

- Audit proposed exclusions as carefully as retained claims: source-backed related examples need not prove the entire article or repeat its exact heading. Distinguish true wrong-topic material from supported narrow controls, inspect the current relation target, and preserve evidence through scoped repairs rather than blanket quarantine.

- Keep lesson-local timing definitions and drill conditions: peak may mean forward-swing start in one lesson and actual contact apex in another; synchronized apex contact in a nonattack/defense drill is not every-rally guidance. A source-local racket-region observation or deictic contact point must not become universal contact geometry. Record supported controls as well as failures.

- A serve destination on the opponent forehand does not establish the hitter stroke side. A practice completion target is not automatically a sequential drill. Keep personal spacing preferences attributed, and require every citation own the mechanics/conditions it claims even when other article sources support a broad synthesis.

- Distinguish actor, target and method before combining advice: attacker disrupting a blocker is not defender block variation; serve to backhand is not backhand serve; a flick-specific gripping cue is not every-stroke timing. Different source methods may support different spin choices, so retain attribution/conditions instead of publishing a universal impossibility or deleting valid alternatives.

- Preserve rule precedence and source phases: fast-ball compactness can override distance-based backswing growth. A truncated tail cannot prove a full footwork prescription. Do not universalize a speaker own recovering foot or combine lowered/propped elbow cues from different strokes into invented left-hand/shoulder support.

- Check article/evidence polarity together: an evidence excerpt can correctly warn against tight grip while the article still recommends it. Prioritize confirmed opposite instructions over prose cleanup, correct the false label/body within the same topic with archival history, retain the source condition and independently review the complete final plan before application.

- Quota gates must use actual account windows,not local token totals or primary/secondary position. Test exactly600/601 seconds,keep weekly cutoff independent,and defer on unavailable/expired snapshots. Optional localbudget disable must not bypass an enabled account guard.


- Do not forecast remaining audit duration from a mix of initial coverage,configurationwork andsmall repair releases. Measure representative final-clearance batches. Explicitly reviewed deletion of unsupported optional metadata does not need generative drafting; batching validation saves time without dropping release gates.

- Split advisory overlap freshness from actual claim/source/target dependencies, but retain an explicit overlap review that blocks completion. Bootstrap legacy fingerprints only when the original full dossier still matches; otherwise old decisions lack proof of freshness.
- Measure whole safe application transactions separately from model/source review. A fast scratch transaction benchmark does not establish semantic throughput or justify a new completion forecast. Test external writes and retain transaction recovery when reusing post-application state.

- A rejected quarantine can itself block future correction when the repair selector excludes every quarantined unit. Keep explicit restoration as reviewed work; never silently reapprove the record or delete valid source material to match an overbroad draft definition.
- Keep semantic model time,account quota,processor tokens,parent review cost,application cost and local startup delays separate. Passing a frozen referent pair does not prove general accuracy or justify a remaining-hours forecast from a mixed20article batch.

- A bounded function inside python -i is not a bounded process: the interpreter survives at its prompt. Use finite CLI jobs and verify saved completion before saying a background audit is running. Distinguish actual task completion from client spinner/session routing; recovered network events and shutdown EPIPE are not automatically a hang root cause.

- Final primary review must include unchanged inherited evidence when new source reading exposes an error. A generic topic qualifier cannot come from a separate unrelated citation; hook-serve backhand bat surface is not backhand-stroke identity. Preserve the actual long-ball condition when neighboring text says a fundamental technique also works short.

- Exact-source verification should accept a clear question-and-answer together, even when the following caption is unfinished. Spelling normalization in paraphrases is different from claiming a corrected verbatim quotation. Keep actual over-rejection cases alongside false-acceptance controls;neither model verdict nor earlier primary review is infallible.
